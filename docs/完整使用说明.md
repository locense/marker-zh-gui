# Marker 2.0 本地 Docker 部署说明（Windows + NVIDIA GPU）

本文档对应 `<项目目录>\deploy` 目录下的实际部署，已于 2026-10-16 完成 GPU 转换验证。

## 一、这是什么

Marker 用于把 PDF 转换成 Markdown、JSON、HTML 等格式。本项目采用“客户端 + GPU 推理服务”两层结构：

| 容器 | 作用 |
|---|---|
| `marker-vllm` | GPU 推理服务，运行 `datalab-to/surya-ocr-2` 模型，监听 `127.0.0.1:18100` |
| `marker-client` | Marker 2.0.0 转换客户端，运行在 CPU 上，通过 Docker Compose 内网连接 GPU 服务 |

GPU 加速由 vLLM 容器承担；Marker 客户端保持轻量。模型和下载缓存保存在 Docker 命名卷中，删除容器不会丢失模型。

## 二、已验证环境

- 操作系统：Windows + Docker Desktop 4.46.0
- GPU：NVIDIA GeForce RTX 4060 Laptop，8 GB 显存
- `marker-pdf`：2.0.0
- 推理后端：`vllm/vllm-openai:v0.20.1`
- Docker 镜像：`local/marker-pdf:2.0.0`（约 1.76 GB）

实测结果：

- vLLM 日志多次出现 `POST /v1/chat/completions` 并返回 `200`
- 生成吞吐实测 18.4 → 35.9 tokens/s
- 显存稳定占用约 6.4～6.5 GB / 8 GB
- 预热完成后，单页 PDF 转换约 15～16 秒

## 三、首次启动

打开 PowerShell，执行：

```powershell
cd <项目目录>\deploy
docker compose up -d vllm
docker compose ps
```

第一次启动需要下载模型并预热推理引擎，耗时较长。当 `docker compose ps` 显示 `marker-vllm` 为 `healthy` 时，服务才算就绪。

查看启动日志：

```powershell
docker compose logs -f vllm
```

按 `Ctrl+C` 退出日志查看不会停止容器。

## 四、日常使用

### 1. 启动服务

Docker Desktop 开机自启时，容器通常会自动恢复。若未启动，执行：

```powershell
cd <项目目录>\deploy
docker compose up -d vllm
```

确认状态：

```powershell
docker compose ps
```

看到 `healthy` 即可使用。

### 2. 放入待转换文件

把 PDF 或图片复制到：

```text
<项目目录>\inputs
```

### 3. 执行转换（推荐 PowerShell）

```powershell
cd <项目目录>\deploy
.\convert.ps1 ..\inputs\你的文件.pdf
```

也可以使用 `.cmd` 版本：

```bat
cd /d <项目目录>\deploy
convert.cmd ..\inputs\你的文件.pdf
```

### 4. 查看结果

输出目录为：

```text
<项目目录>\outputs\<文件名>\
```

其中包含：

- `<文件名>.md`：转换后的 Markdown 正文
- `<文件名>_meta.json`：页面与模型元数据

## 五、图形界面（marker-gui）

除了命令行，本项目还提供基于 Streamlit 的官方图形界面，浏览器打开：

```text
http://127.0.0.1:18102
```

启动图形界面服务：

```powershell
cd <项目目录>\deploy
docker compose --profile gui up -d gui
```

界面功能：

- 一次可上传并转换多个文件（批量模式）
- 支持 PDF、图片（自动转 PDF）、DOCX、PPTX、XLSX、HTML、EPUB
- 左侧预览页面，可切换页码
- 选择输出格式：markdown / json / html / chunks
- 选择模式：auto / balanced / fast
- 勾选使用 LLM、强制 OCR、禁用 OCR、移除已有 OCR、保留页眉页脚等
- 每个文件都有独立的“下载”按钮
- 多文件时提供“打包下载全部结果”按钮，生成 `marker_results.zip`
- 结果会保留在当前浏览器会话中，直到点击“清空结果”

图形界面与命令行共用同一个 GPU 推理服务 `marker-vllm`，转换质量完全一致。

停止图形界面：

```powershell
docker compose --profile gui stop gui
```

如需开机自动启动图形界面，可从 `deploy\docker-compose.yml` 的 `gui` 服务中删除 `profiles: ["gui"]` 一行，之后 `docker compose up -d` 会一并启动。
## 六、常用参数

### 强制 OCR（扫描版 PDF 推荐）

```powershell
.\convert.ps1 ..\inputs\扫描件.pdf --force_ocr
```

### 只转换指定页

页码从 0 开始：

```powershell
.\convert.ps1 ..\inputs\论文.pdf --page_range "0,5-10,20"
```

### 输出 JSON 或 HTML

```powershell
.\convert.ps1 ..\inputs\论文.pdf --output_format json
.\convert.ps1 ..\inputs\论文.pdf --output_format html
```

### 使用 fast 模式（更快，质量略低）

```powershell
.\convert.ps1 ..\inputs\论文.pdf --mode fast
```

不加 `--mode` 时默认使用 `balanced`，即 GPU 高质量模式。

### 不提取图片

```powershell
.\convert.ps1 ..\inputs\论文.pdf --disable_image_extraction
```

完整参数列表可通过下面命令查看：

```powershell
docker compose --profile cli run --rm --entrypoint marker_single marker --help
```

## 七、日常维护命令

```powershell
cd <项目目录>\deploy

docker compose ps                      # 查看状态
docker compose logs --tail 200 vllm    # 查看 GPU 服务日志
docker compose restart vllm            # 重启 GPU 服务
docker compose down                    # 停止容器（保留模型缓存）
docker compose up -d vllm              # 重新启动
```

不要随意执行 `docker compose down -v`，该命令会删除模型缓存卷，下次启动需要重新下载模型。

## 八、8 GB 显存调优

当前 `docker-compose.yml` 使用保守配置：

```text
--max-model-len 8192
--max-num-seqs 8
--gpu-memory-utilization 0.72
```

如果 vLLM 因显存不足退出，可在 `docker-compose.yml` 中依次尝试：

1. 把 `--gpu-memory-utilization` 从 `0.72` 降到 `0.65`
2. 把 `--max-model-len` 从 `8192` 降到 `4096`
3. 把 `--max-num-seqs` 从 `8` 降到 `4`
4. 关闭浏览器、游戏等占用显存的程序

修改后执行：

```powershell
docker compose up -d --force-recreate vllm
```

## 九、常见问题

### 1. `marker-vllm` 一直是 starting

模型首次下载和引擎预热需要时间，查看日志确认进度：

```powershell
docker compose logs -f vllm
```

看到 `Application startup complete` 后健康检查会转为 `healthy`。

### 2. 提示找不到输入文件

输入文件名必须真实存在于 `<项目目录>\inputs`。脚本只按文件名传入容器，传参时举例：

```powershell
.\convert.ps1 ..\inputs\report.pdf
```

### 3. 打开 `http://127.0.0.1:18100/health` 返回 `{}`

这是正常的。该接口只要返回 HTTP 200 即表示服务健康。

### 4. 端口冲突

`marker-vllm` 使用本机 `18100` 端口。如果被占用，修改 `docker-compose.yml` 中的端口映射，例如改成 `18101:8000`，并把 `marker` 服务中的 `SURYA_INFERENCE_URL` 同步改为 `http://vllm:8000/v1`（容器内仍走 8000）。

### 5. Docker 拉取镜像很慢

本机已清除失效镜像源，Docker 走 Docker Desktop 代理 → Clash `127.0.0.1:7897`。若重新变慢，检查：

```powershell
docker info --format 'Mirrors={{json .RegistryConfig.Mirrors}} HTTPProxy={{.HTTPProxy}}'
```

正常情况下 `Mirrors` 为空。

## 十、配置 LLM（DeepSeek）

Marker 的 `--use_llm` 模式默认使用 Google Gemini，因此不配置时会报：

```text
AssertionError: In order to use GoogleGeminiService, you must set the configuration values `gemini_api_key,`.
```

本项目已改为使用 DeepSeek 的 OpenAI 兼容接口。

### 1. 需要改哪个文件

只改这一个文件：

```text
<项目目录>\deploy\llm-config.json
```

把其中的 `openai_api_key` 换成你的 DeepSeek API Key：

```json
{
  "llm_service": "marker.services.openai.OpenAIService",
  "openai_base_url": "https://api.deepseek.com",
  "openai_model": "deepseek-flash",
  "openai_api_key": "sk-你的DeepSeek密钥",
  "openai_image_format": "png",
  "timeout": 120,
  "max_retries": 2
}
```

说明：

- `openai_model` 必须是 `deepseek-flash`，这是 DeepSeek 当前支持图片输入的模型
- `deepseek-v4-pro` 不支持视觉输入，Marker 会传图片给它，因此不能用
- `openai_base_url` 写 `https://api.deepseek.com` 即可，Marker 会自动请求 `/chat/completions`
- 该文件会只读挂载到容器的 `/config/llm-config.json`

### 2. 让配置生效

图形界面修改密钥后需要重建容器：

```powershell
cd <项目目录>\deploy
docker compose --profile gui up -d --force-recreate gui
```

命令行转换无需重启，每次运行都会读取该文件。

### 3. 图形界面使用

页面左侧勾选 **Use LLM**，再点击 **Run Marker**，即走 DeepSeek。

### 4. 命令行使用

```powershell
cd <项目目录>\deploy
docker compose --profile cli run --rm marker /inputs/你的文件.pdf `
  --output_dir /outputs `
  --use_llm `
  --llm_service marker.services.openai.OpenAIService `
  --config_json /config/llm-config.json
```

配置文件和输入输出目录一样已挂载进客户端容器，无需额外参数。

### 5. 是否必须配置

不是。`--use_llm` 是可选增强项，主要改善跨页表格合并、行内公式、表单字段提取等。普通文档只用 GPU OCR 即可获得良好结果，不勾选 **Use LLM** 不会产生任何 API 费用。

文件：`%USERPROFILE%\.docker\daemon.json`

已移除失效的 `registry-mirrors` 列表，只保留代理链路；备份文件为同目录下的 `daemon.json.bak-20261016`。
